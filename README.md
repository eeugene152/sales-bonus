## Описание проекта
По собранным в датасете данным о продажах в магазине необходимо составить рейтинг продавцов по доходности и рассчитать бонусы для каждого продавца.

## Структура проекта
1. `data` - каталог с примерами данных
2. `src/main.js` - основной файл программы
3. `index.html` - файл для запуска программы

## Инструкция по запуску
Открыть любым способом файл `index.html` в браузере. В консоли DevTools (CTRL+Shift+I) будет выведен рейтинг продавцов и рассчитанные бонусы.

Чтобы изменить выбранный датасет, необходимо в файле `index.html` изменить ссылку в строке:
```html
<script src="data/dataset_1.js"></script>
```
Доступны 3 примера дата-сетов:
- `data/dataset_1.js`
- `data/dataset_2.js`
- `data/dataset_3.js`

# Задача
Реализовать подготовленные, но не заполненные функции опираясь на комментарии в коде.
Можно добавлять собственные функции и изменять код внутри функций, но не изменять имена функций и код запуска в `index.html`.

## Ключевые требования
- Программа написана на чистом JS без использования сторонних библиотек;
- Из основной функции анализа выделены функции для расчета прибыли и бонусов, что позволяет корректировать особенности расчетов без изменения основного кода;
- Используйте только чистые функции (функция получает все что ей необходимо для работы через аргументы), не обращающиеся к глобальным переменным и не имеющие побочных эффектов.

## Что было реализовано в ходе работы
В процессе выполнения проекта были решены следующие архитектурные и алгоритмические задачи:

*   **Инверсия управления (IoU)**: Главная функция анализа `analyzeSalesData` полностью отвязана от конкретных формул. Она принимает функции расчета выручки и бонусов снаружи через объект `options`, что делает аналитику легко масштабируемой.
*   **Индексация данных для оптимизации O(N)**: Чтобы избежать ресурсоемких вложенных циклов и повторных поисков через `.find()`, исходные массивы справочников (товары и продавцы) были преобразованы в быстрые хэш-таблицы (объекты-словари) с помощью метода `.reduce()`. Это позволило провести все расчеты по чекам всего за один проход по массиву.
*   **Глубокая трансформация коллекций**: Реализована многоступенчатая конвейерная обработка данных с использованием методов `.map()`, `.sort()`, `.slice()` и `Object.entries()`. Данные динамически пересобирались из объектов в массивы «кортежей», сортировались и возвращались обратно в нужный вид по ТЗ.
*   **Ранжирование и фильтрация (Топ-10)**: Написан чистый алгоритм для подсчета персональной статистики продаж каждого сотрудника, вычисления топ-10 самых продаваемых им товаров и сортировки их по объему продаж.
*   **Улучшение читаемости (Паттерн Early Return)**: Логика распределения бонусов в зависимости от места в рейтинге была избавлена от громоздких «лестниц» `if / else if` и переписана с использованием концепции раннего возврата, что сделало код линейным и строгим.

## Преодоленные трудности и особенности JS
Переход на JavaScript после опыта работы с Python (бэкенд) принес интересные вызовы, которые были успешно решены:

1.  **Потеря точности копеек (Стандарт IEEE 754)**: Из-за специфики работы с числами с плавающей точкой в JS, при многократном сложении сумм чеков накапливалась микроскопическая погрешность (появлялись хвосты вроде `.000000000003`). Проблема была решена за счет отказа от промежуточных округлений в циклах. Все «грязные» числа копились до самого конца и округлялись методом `.toFixed(2)` строго один раз на этапе формирования финального отчета.
2.  **Контроль мутации данных**: В отличие от Python, где копирование объектов более явное, в JS объекты и массивы всегда передаются по ссылке. Были детально изучены механизмы работы методов, изменяющих оригинал (например, `.sort()`), и методов, возвращающих чистую копию (например, `.slice()`). Вся цепочка расчетов была построена так, чтобы исходный датасет оставался чистым.
3.  **Особенности сортировки строк**: Было выявлено, что математическое вычитание применимо только к числам, а попытка отсортировать артикулы (SKU) через дефис приводит к `NaN`. Для строгой алфавитной сортировки строк был успешно внедрен метод `.localeCompare()`.
4.  **Поведение объектов в JS**: Было учтено, что в JS обычные объекты `{}` не гарантируют строгий порядок своих ключей. Поэтому для сохранения четкой последовательности элементов (в рейтингах и топах товаров) данные были зафиксированы в виде массивов объектов, как того и требовало ТЗ.
